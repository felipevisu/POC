Zod vs Yup

Two TypeScript schema validation libraries, compared with real code

Round 1: Type inference defaults

Yup: optional by default


const userSchema = yup.object({
  name: yup.string(),
  age: yup.number(),
});

type User = yup.InferType<typeof userSchema>;
// {
//   name?: string | undefined;
//   age?: number | undefined;
// }

Zod: required by default


const userSchema = z.object({
  name: z.string(),
  age: z.number(),
});

type User = z.infer<typeof userSchema>;
// {
//   name: string;
//   age: number;
// }

Same-looking schema, opposite inferred types. Yup needs .required() everywhere; Zod needs .optional() only where you mean it.

Round 2: Saying what you mean

Yup


const schema = yup.object({
  email: yup.string().email().required(),
  nickname: yup.string(),
});
// { email: string; nickname?: string }

Zod


const schema = z.object({
  email: z.email(),
  nickname: z.string().optional(),
});
// { email: string; nickname?: string }

Both can express the same type; the difference is which direction you annotate. Zod's default matches how most API types actually look.

Round 3: Error handling

Yup: throws, try/catch


try {
  await schema.validate(
    { name: 123, age: "x" },
    { abortEarly: false } // default: stops at 1st error!
  );
} catch (err) {
  if (err instanceof yup.ValidationError) {
    console.log(err.inner); // all errors
  }
}

Zod: result object


const result = schema.safeParse(
  { name: 123, age: "x" }
);

if (!result.success) {
  console.log(result.error.issues);
  // all errors, always
}

Yup aborts early unless you remember { abortEarly: false }. Zod's safeParse never throws and always collects every issue.

Round 4: Sync vs async

Yup: async by default


// always a Promise, even for min(3)
const promise = schema.validate({ username: "ana" });

// validateSync exists, but throws
// if the schema has ANY async test
asyncSchema.validateSync({ username: "ana" }); // 💥

Zod: sync by default


// immediate result, no await
const result = schema.safeParse({ username: "ana" });

// async only when YOU add async logic,
// and zod forces the explicit switch:
await asyncSchema.safeParseAsync({ username: "ana" });

With Yup you pay the Promise tax on every validation. With Zod, async is opt-in and the API makes the boundary explicit.

Round 5: Conditional validation

Yup: .when() built in


const schema = yup.object({
  deliveryMethod: yup.string()
    .oneOf(["pickup", "ship"]).required(),
  address: yup.string().when("deliveryMethod", {
    is: "ship",
    then: (s) => s.required(),
    otherwise: (s) => s.strip(),
  }),
});
// InferType: address?: string
// (type can't see the condition)

Zod: discriminated union


const schema = z.discriminatedUnion("deliveryMethod", [
  z.object({ deliveryMethod: z.literal("pickup") }),
  z.object({
    deliveryMethod: z.literal("ship"),
    address: z.string(),
  }),
]);
// type Order =
//   | { deliveryMethod: "pickup" }
//   | { deliveryMethod: "ship"; address: string }

Yup's .when() is ergonomic but invisible to the type system. Zod encodes the condition in the type itself (.refine() as fallback).

Round 6: Behavior at the API boundary

InputYupZod
age: "30" (string) ✅ passes (casts to number) ❌ fails (no silent coercion)
extra key role: "admin" kept in output stripped from output
OpenAPI / JSON Schema needs 3rd-party lib z.toJSONSchema(schema) built in

Yup was born for forms (casting is a feature there). Zod behaves like a strict API contract.

Final round: dependencies

Yup


"dependencies": {
  "property-expr": "^2.0.5",
  "tiny-case": "^1.0.3",
  "toposort": "^2.0.2",
  "type-fest": "^2.19.0"
}

Zod


"dependencies": {}

Zod is zero-dependency.

  • Nothing else enters your node_modules: smaller install, smaller attack surface
  • No transitive packages to audit, patch, or get supply-chain-attacked through
  • No version conflicts with the rest of your dependency tree
  • The whole library is one self-contained import that works the same in Node, browsers, edge runtimes
